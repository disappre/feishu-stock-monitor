# 知识库（Agent 记忆层）

本目录是监测系统 agent 的长期记忆，按三层存储：

```
knowledge/
├── README.md            # 本文件：规范
├── patterns/            # 形态类知识卡片（每形态一卡）
├── indicators/          # 指标类知识卡片
├── strategies/          # 策略与经验类卡片
└── sources.md           # 原文档案索引（只存 URL/摘要，不存全文）
```

## 三层存储原则

| 知识性质 | 去处 | 例子 |
|---------|------|------|
| 确定性规则（公式/阈值/几何条件） | **代码 + 单元测试** | 螃蟹形态的斐波那契比例 → `rules_harmonic.py` |
| 陈述性知识（概念/适用场景/坑） | **知识卡片**（本目录，进git） | "谐波形态只在震荡市可靠，单边市D点易失效" |
| 原始素材 | **sources.md 索引**（URL+摘要） | MQL5文章链接 |

铁律：**知识卡片不复制大段原文**，用自己的话压缩成 agent 能直接引用的结论；卡片里的数值参数必须与代码保持一致，代码改了卡片同步改。

## 原文获取管道（浏览器优先）

本地直连 mql5.com 等站点常超时，标准流程是**浏览器下载 → 本地入库**：

1. 浏览器打开文章 → `Ctrl+S` 保存为"仅HTML"（或打印为PDF）→ 存入 `knowledge/inbox/`；
2. 运行 `python tools/ingest_local.py` → 自动转 Markdown（剔除脚本、带元信息头）
   存入 `knowledge/archive/`，原件移入 `inbox/done/`；
3. 让 agent 按 knowledge-intake 流程提炼 archive/ 里的文章（三层分流），
   完成后在 `sources.md` 登记并把条目移出 `reading-list.md`。

agent 可服务端读取的 URL（如 WebFetch 可达），可跳过浏览器直接提炼。
`archive/` 与 `inbox/` 不入 git（.gitignore 已排除），只作为中转暂存。

## 知识卡片模板

```markdown
# <知识名称>
- 来源: <URL或出处> / <抓取日期>
- 关联代码: <stock_monitor/xxx.py>

## 一句话结论
<30字以内，agent检索时最先看到的>

## 核心规则
<判定条件，能写成伪代码就写伪代码；与代码实现一致>

## 适用与失效
- 适用: <什么市场/什么股性下可靠>
- 失效: <什么情况下会错，历史教训>

## 参数依据
<参数取值的出处或回测依据，没有就写"未验证">

## 变更记录
- 2026-09-08 初版，提炼自 <来源>
```

## 与 agent 的接法（按项目演进顺序）

1. **现在**：卡片只给人看 + 给 LLM 当 prompt 素材（`llm/interpreter.py` 可按信号类型检索对应卡片注入解读上下文）；
2. **下一步**：接入 Dify 知识库——把 `knowledge/` 目录批量上传，工作流里信号触发时自动检索对应卡片，实现"解读时引用学过的知识"；
3. **远期**：多维表格复盘胜率回流 → 卡片的"适用与失效"段落用真实数据更新，形成记忆的自我修正。
