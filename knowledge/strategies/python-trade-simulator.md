# Python自研交易模拟器（回测架构设计）

- 来源: https://www.mql5.com/zh/articles/18971 / 2026-09-09
- 关联代码: 暂未实现（用途：监测系统信号的历史回测，补齐"信号胜率"验证环节）

## 一句话结论

不依赖MT5回测器，用Python类自建"持仓/挂单/成交记录"三套账本的交易模拟器，参数风格贴近MT5策略测试器面板。

## 核心设计（文章架构提炼）

```
TradeSimulator 类核心状态:
  position_info: time/id/magic/symbol/type/volume/open_price/price/sl/tp
  pending_orders: 挂单生命周期(创建→监控→成交/删除/修改)
  deal_history: 成交记录

职责清单: 持仓盈亏计算 / 模拟持仓开平 / 交易参数校验 /
         持仓监控 / 挂单CRUD与监控 / 多实例隔离(simulator_name区分文件夹)
```

## 适用与失效

- 适用: 项目当前最大空白——8个规则+聚类模型的信号从未被历史回测验证过。
  本地SQLite已有250根×300只日线，正是这个模拟器的喂料
- 失效/教训: 文章是MT5对接版(mt5_instance)；本项目应替换为"逐根K线推进"
  的纯本地事件驱动回放，不需要MT5
- 对本项目的映射: 信号≠交易。回测需要把Signal翻译成"入场价(次日开盘)/
  持有N日/止损止盈规则"三要素，这正是多维表格复盘字段(信号→N日后涨跌)的
  代码化版本

**核心教训**：①单一市场状态样本会"自信地给出错误结论"，数据长度是可信度第一约束；
②两年数据的真实规律=回避类信号(超买/破位)稳定有效、看涨类信号全部无效——
与A股做空受限但可空仓的制度特点自洽；③"参数不写回配置"的红线避免了固化过拟合。
