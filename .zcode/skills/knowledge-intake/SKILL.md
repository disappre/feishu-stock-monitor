# 知识入库（Knowledge Intake）

把用户提供的知识按性质分三层存储，让 agent 长期可用。

## 工作流程

### 第1步：三层分流（对每份知识逐条判断）

```
能写成精确判定条件吗？（公式/阈值/几何比例/伪代码）
 ├─ 能 → 第1层【代码化】：实现到 stock_monitor/engine/ 对应模块 + tests/ 单元测试，
 │        并在知识卡片"参数依据"注明出处；禁止只写卡片不写代码
 └─ 不能 → 是可复用的结论/经验吗？
     ├─ 是 → 第2层【知识卡片】：按下方模板新建 knowledge/<分类>/<slug>.md
     └─ 原始素材 → 第3层【索引】：仅在 knowledge/sources.md 追加一行
```

分类目录：`patterns/`（形态）、`indicators/`（指标）、`strategies/`（策略与经验）。
拿不准放哪层时，问用户；用户不在场时宁可多建卡片（第2层），不要丢弃。

### 第2步：知识卡片必须遵守

1. **用自己的话压缩，禁止复制大段原文**——每张卡以"30字以内一句话结论"开头；
2. 固定字段（模板见 knowledge/README.md）：来源URL+日期 / 关联代码 / 一句话结论 /
   核心规则 / 适用与失效 / 参数依据 / 变更记录；
3. 数值参数若来自外部文章而非本项目回测，必须标注【待验证】；
4. 卡片中的参数与 engine/ 代码必须一致——写代码时改了默认值，卡片同步改，反之亦然。

### 第3步：登记与收尾

- 无论提炼到哪层，都在 `knowledge/sources.md` 追加一行索引（日期/链接/三句话摘要/产出文件）；
- 向用户汇报：提炼出了什么（几条规则、几张卡片）、分别存到了哪层、
  哪些参数待验证、是否需要实现对应代码。

## 红线

1. 禁止把原文大段存入任何一层（sources.md 只存 URL+摘要）；
2. 禁止把未经验证的外部参数写成确定结论；
3. 涉及具体股票的买卖观点不是"知识"，拒绝入库；本知识库只收方法论。
